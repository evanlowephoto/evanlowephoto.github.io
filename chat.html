Talk to Tiny Tim — Whisper in, voice out

Tap the mic in the chat, speak, tap again. OpenAI's Whisper (the tiny English model, via Transformers.js / Hugging Face) transcribes right in your browser — your voice is not uploaded for transcription. Tiny Tim's reply is then spoken back in the voice you pick. Six neural voices from Kokoro — a free, open-source voice model that generates speech right on this device, so Tiny Tim sounds like himself for every visitor instead of borrowing whatever generic voice a phone happens to ship:

How the voices work: every voice is generated by the Kokoro-82M neural model (free and open-source, Apache-2.0 — no account, no key, no cost), downloaded once (~92 MB) from Hugging Face and cached by your browser; after that, speech is made entirely on this device and nothing is recorded or sent anywhere to produce it. The first spoken reply can take a little while on a slow connection while the model warms up. If the neural model cannot load on a device, Tiny Tim falls back to the browser's built-in voice and the status line above the chat says so — speech never just goes silent without an explanation. First talk also downloads Whisper once (~40 MB) for transcription. Mic access needs your permission; if talk-to-text fails, the status line names the reason — permission denied, no mic found, a silent or blocked mic track, or the model itself — instead of doing nothing.

Phase 0 — CLIP matched against your field lists

No training, no new weights. The CLIP row in every vision report now classifies against label lists built from your own archive and your confirmed IDs, instead of generic subjects. Each class is scored with 8 prompt templates (“a photo of a…”, “a close-up macro photo of a…”, “a wild … in nature”, “a … in Indiana”, and four more), the scores are averaged, and the top 5 are shown with scores — worded as candidates, not an identification, every time. Common names lead; the scientific name and a short visual phrase sit alongside.

Paste the Llama API key from your own account at api.llama.com and pick a model. Replies — and picture descriptions — then come from the real model, straight from your browser. No key? It stays in demo mode.

Not connected — demo mode

Where the key lives: in this tab's memory only — never saved, wiped on refresh. Pictures you attach are resized in your browser and sent only to the Llama API, as part of your message. Attached pictures also get a vision report from seven open-source models that run on this device — COCO-SSD quick tags and a MobileNet classifier (both TensorFlow.js, the runtime already proven to load here, so classification still works if Transformers.js cannot) plus five Hugging Face models via Transformers.js: a ViT classifier, a DETR detector that draws boxes, a ViT-GPT2 captioner, CLIP zero-shot matching (Phase 0: scored against the field label lists above with 8 prompt templates per class, top 5 shown), and OwlViT zero-shot detection. Each model downloads from its public CDN/Hugging Face repo on first use and is then cached by your browser; the picture itself is not uploaded for local analysis. The other models return generic labels, and CLIP's field-list matches are candidates, not an identification. Voice is separate: Whisper transcription runs on-device, and only the transcribed text follows the normal chat path above (demo reply, or the Llama API when connected).

System check — is Tiny Tim actually running?

One tap tests everything on this device, in order: browser features, the two model libraries, a smoke run that makes the Transformers.js engine actually compute something (a tiny embedding model, run end-to-end), then each of the eight on-device models loaded one at a time (Whisper, COCO-SSD, MobileNet, ViT, DETR, captioner, CLIP, OwlViT). Nothing here rides on a single host: the libraries are served by two CDNs (jsDelivr and unpkg) and the model files by two hosts (Hugging Face and its hf-mirror.com mirror), each tried in turn — one host being down or blocked no longer fails the whole test. First run downloads the models, so it can take a few minutes on a slow connection; after that they are cached and the test is fast. A quick browser-features check runs by itself when the page opens — the model libraries load on first use, and the full test only runs when you tap it. Any check that fails is retried automatically for up to 3 rounds with a short pause between rounds — each retry tries the other host or load method — and then the test ends with an honest verdict instead of retrying forever. Every check has a time limit so a stalled load fails by name instead of hanging, clears the stuck work out of the way, and lets the next round start clean. Picture reports also include a MobileNet classifier on TensorFlow.js — the runtime already proven to load here — so a picture still gets a real on-device classification even if the Transformers.js models cannot load.

Stop testing ends the run after the current check and reports honestly how far it got; after 3 rounds the test ends and the failed rows stand as the verdict.
