Talk to Tiny Tim — Whisper in, voice out

Tap the mic in the chat, speak, tap again. OpenAI's Whisper (the tiny English model, via Transformers.js / Hugging Face) transcribes right in your browser — your voice is not uploaded for transcription. Tiny Tim's reply is then spoken back in the voice you pick. Six generic voices, female to male:

How the six voices work: each preset first tries to match a matching voice already on your device (for example a female or male system voice), then shapes it with pitch and pace — so the same six settings sound a little different on every phone and computer. First talk downloads Whisper once (~40 MB) and your browser caches it. Mic access needs your permission, and if this browser has no mic or no speech voices, the buttons say so instead of pretending.

Phase 0 — CLIP matched against your field lists

No training, no new weights. The CLIP row in every vision report now classifies against label lists built from your own archive and your confirmed IDs, instead of generic subjects. Each class is scored with 8 prompt templates (“a photo of a…”, “a close-up macro photo of a…”, “a wild … in nature”, “a … in Indiana”, and four more), the scores are averaged, and the top 5 are shown with scores — worded as candidates, not an identification, every time. Common names lead; the scientific name and a short visual phrase sit alongside.

Not connected — demo mode

Where the key lives: in this tab's memory only — never saved, wiped on refresh. Pictures you attach are resized in your browser and sent only to the Llama API, as part of your message. Attached pictures also get a vision report from six open-source models that run on this device — COCO-SSD quick tags (TensorFlow.js) plus five Hugging Face models via Transformers.js: a ViT classifier, a DETR detector that draws boxes, a ViT-GPT2 captioner, CLIP zero-shot matching (Phase 0: scored against the field label lists above with 8 prompt templates per class, top 5 shown), and OwlViT zero-shot detection. Each model downloads from its public CDN/Hugging Face repo on first use and is then cached by your browser; the picture itself is not uploaded for local analysis. The other models return generic labels, and CLIP's field-list matches are candidates, not an identification. Voice is separate: Whisper transcription runs on-device, and only the transcribed text follows the normal chat path above (demo reply, or the Llama API when connected).

System check — is Tiny Tim actually running?

One tap tests everything on this device, in order: browser features, the two model libraries, a smoke run that makes the Transformers.js engine actually compute something (a tiny embedding model, run end-to-end), then each of the seven on-device models loaded one at a time (Whisper, COCO-SSD, ViT, DETR, captioner, CLIP, OwlViT). Nothing here rides on a single host: the libraries are served by two CDNs (jsDelivr and unpkg) and the model files by two hosts (Hugging Face and its hf-mirror.com mirror), each tried in turn — one host being down or blocked no longer fails the whole test. First run downloads the models, so it can take a few minutes on a slow connection; after that they are cached and the test is fast. A quick library check runs by itself when the page opens — the full test only runs when you tap it. The test keeps testing until it knows: any check that fails is retried automatically, round after round (up to three rounds on the full test), and every check has a time limit so the run always ends with a verdict instead of hanging.
